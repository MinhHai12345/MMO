# Provider master data discovery

## Purpose

The discovery endpoint reads provider catalogues and returns a snapshot for review. It does not persist leagues, seasons, teams, external mappings, or modify the canonical JSON seed.

## Endpoint

`POST /api/fb/master-data/discovery`

Required header: `X-Ingestion-Admin-Key`, using `app.ingestion.operations.api-key`.

Example request:

```json
{
  "providers": ["SOFA_SCORE", "UNDER_STATS", "FOOTBALL_DATA", "API_FOOTBALL"],
  "externalLeagueIds": [],
  "teamQueries": [
    {
      "provider": "SOFA_SCORE",
      "leagueId": 17,
      "season": "2025/2026",
      "leagueIdentify": null
    },
    {
      "provider": "UNDER_STATS",
      "leagueId": null,
      "season": "2025",
      "leagueIdentify": "EPL"
    }
  ]
}
```

Omit `providers` or pass an empty list to inspect every configured provider adapter. Omit `teamQueries` to avoid team-catalogue fan-out. Team queries must be explicit and provider-specific.

## Current adapter capabilities

| Provider | League catalogue | Season catalogue | Team catalogue |
|---|---|---|---|
| SofaScore | Yes; league response includes seasons | Embedded in league catalogue | Yes; requires league ID and season |
| Understat | Yes | Yes; supported season range is generated by adapter | Yes; requires league identify and season |
| Football-Data.org | Yes | Embedded in competition response when supplied by source | Yes; requires competition ID and season |
| API-Football | Yes | Not currently exposed through a season ingestion port | Yes; requires league ID and season |
| Football-Data.co.uk | No standalone catalogue port; league codes are initialized in the historical importer | Season rows are prepared by the historical importer | Teams are derived from season CSV rows during import |

A provider can return partial data when an adapter call fails or a capability is unavailable. The report includes provider status, warnings, and errors. External IDs are deduplicated only within the same provider and entity type. Conflicting names for the same provider external ID are reported; records from different providers are never merged by name.

## Workflow

1. Run discovery for leagues and embedded/adapter-provided seasons.
2. Review coverage, errors, and external-ID conflicts.
3. Run explicit team queries for selected league-season pairs.
4. Resolve canonical league/season/team identities and review mappings.
5. Only after review, update the canonical JSON and run the initializer in DRY_RUN before APPLY.
